# План — Cookie-согласие + Datenschutz (перед включением Google Signals)

Дата: 2026-07-27.

## Контекст

Стас хочет включить Google Signals в GA4 (кросс-девайсные данные, привязанные к залогиненным Google-аккаунтам — нужно для ремаркетинга/платного трафика). Диалог включения в GA4 прямо требует: сообщить пользователям о сборе таких данных, получить согласие, дать доступ к «Мои действия».

## Аудит (2026-07-27)

- `app/[locale]/layout.tsx:119-122` — GA4 (`G-EKLZT9R83C`) грузится и стартует **безусловно**, без запроса согласия, для каждого посетителя.
- Cookie-баннера / CMP в коде нет вообще.
- Google Consent Mode (`gtag('consent', ...)`) не реализован.
- `/agb` (`app/[locale]/agb/page.tsx`) — это только Allgemeine Geschäftsbedingungen (запись, задаток, отмена, здоровье, ответственность, фото-права). §9 «Datenschutz» — одно общее предложение, не полноценная политика.
- Отдельной страницы Datenschutzerklärung нет — по немецкому праву (§13 TMG / ст.13 DSGVO) она обязательна для любого коммерческого сайта, независимо от Google Signals.
- Google Ads / Meta Pixel тегов нет — сейчас только голый GA4.
- Категория бизнеса (тату) не входит в «чувствительные» у Google — проблем с включением Signals по теме сайта не будет, риск был только в отсутствии инфраструктуры согласия.

**Вывод:** сайт уже сейчас (даже без Google Signals) технически собирает аналитику без согласия — базовый пробел, который нужно закрыть в любом случае. Включать Google Signals поверх этого пробела нельзя — это только увеличит риск, а не просто «дополнительная галочка».

## План реализации

1. **Google Consent Mode v2** — в `app/[locale]/layout.tsx`, перед `gtag('config', ...)`: `gtag('consent','default',{ analytics_storage:'denied', ad_storage:'denied', ad_user_data:'denied', ad_personalization:'denied' })`. GA4-скрипт продолжает грузиться для всех (это ок и ожидаемо Google), но не пишет cookies/данные, пока нет согласия.
2. **Баннер согласия** — новый клиентский компонент в стиле сайта (`--g-*` токены), 2 кнопки (принять / отклонить), хранит выбор (localStorage), на «принять» — `gtag('consent','update',{...granted...})`.
3. **Страница `/datenschutz`** — по образцу `/agb` (DE-only, `robots: noindex,follow`, тот же SECTIONS-паттерн): Verantwortlicher, Hosting, данные из форм записи/контакта, GA4 + Google Signals (кросс-девайс, ссылка на Google Ads Settings / «Мои действия»), Cookies/Consent, фото-права (ссылка на §9 AGB), права пользователя (доступ/удаление/возражение/жалоба в надзорный орган).
4. **Ссылка в футере** (`GFooter.tsx`, массив `POLICIES`) — рядом с AGB.
5. Только после пунктов 1-4 — идти в интерфейс GA4 и включать Google Signals (это делается в UI, не в коде).

**Важная оговорка:** черновик Datenschutzerklärung ниже написан по стандартной немецкой практике для такого рода сайтов, но это не замена юридической консультации — перед реальным запуском стоит дать финальный текст на быструю проверку юристу/Anwalt, особенно т.к. есть обработка данных о здоровье (§5 AGB) и фото.

## Sitemap

`/datenschutz`, как и `/agb`, **не добавляется** в `sitemap.ts` — юридические страницы туда сейчас не входят (проверено: `/agb` там тоже нет), плюс `robots: noindex` уже сигналит "не индексировать".
