# kisha.tattoo — правила работы

Сайт тату-мастера Киши (Мюнхен), соло-студия. Владелец проекта Стас, общаемся по-русски. Подробности и история решений живут в памяти (`MEMORY.md`). Этот файл держит только то, что нельзя нарушать.

## Главное правило: не сделать хуже

Перед каждой правкой сайта, контента или внешних профилей сначала отвечаем на вопрос «что может стать хуже», и только потом делаем.

1. **Что страница даёт сейчас.** GSC за 90 дней (`npm run google -- gsc --page /x --dims query`), Inspect (`npm run google -- inspect <url>`), цитирует ли её ИИ (`scripts/ai-visibility-*.json`).
2. **Уровень риска.**
   - Топ-10 → не трогаем вообще. Список в памяти `feedback_never_touch_top10`, сейчас это /tattoo-preise-muenchen, /motive, /walk-in-tattoo-muenchen, /en/fineline-tattoo-muenchen, /en/tattoo-preise-muenchen, /tattoo-ottobrunn, /tattoo-freising, /blog/wie-tattoos-altern.
   - Приносит трафик или цитируется ИИ → только дополняем и чиним ошибки. Title, H1, URL и работающие формулировки не меняем.
   - Не в индексе или без показов → можно менять свободно.
3. **Что может сломаться.** Позиции, индексация, ссылки и локали, скорость, вёрстка mobile/desktop, формы и учёт заявок. Если правка может это задеть, проверяем до и после.
4. **Обратимость.** Одна правка = один коммит. Записываем в план дня, что и когда меняли, чтобы потом связать это с GSC.
5. **Проверка после.** Живой сайт после деплоя, не зелёный CI. Через 1–2 недели сверяем GSC с состоянием «до».

Если не ясно, станет ли лучше, ничего не делаем и сначала спрашиваем Стаса, показав цифры.

## Нельзя никогда

Часть правил держит хук `.claude/hooks/guard-bash.py`, но правило действует и там, где хук не видит.

- `git add -A` / `git add .`. В корне лежат PLAN-*.md, Arieta/, analiz/ и ключи, всё это намеренно вне git. Добавлять файлы только по имени.
- Коммитить или выводить в чат `.env.local`, `.google-sa.json`, `.pinterest-token*.json`, `gutscheine/`.
- Деплоить мимо git: rsync, scp, ручные правки на сервере. Force-push.
- `npm run pinterest -- board|unboard`: они создают и удаляют доски в живом аккаунте.
- Менять дизайн и вёрстку в рамках SEO-задачи без ок Стаса. SEO = контент и невидимые атрибуты.
- Онлайн-оплата в формах, адрес студии и «mein Studio» в evergreen-текстах (студия переезжает).
- Публиковать статью без вычитки человеком (AI Act). Постить как работу Киши то, что не её работа.

## Стек

Next.js 15 (App Router) + React 19 + next-intl 4 (de по умолчанию без префикса, `/en`, `/uk`), TypeScript, Vitest, Playwright. Тексты в `messages/{de,en,uk}.json`, статьи блога там же в `blog.stories.<slug>.body` (markdown, ссылки `[текст](/путь)`).

- Ссылки только через `import { Link } from '@/i18n/navigation'`, не `next/link`, иначе теряется локаль. Hreflang только в `HreflangTags` в layout. Подробно в памяти `feedback_i18n_link_traps`.
- Новый `useTranslations` в `'use client'`-компоненте → раздел нужно добавить в `clientMessages()` в `app/[locale]/layout.tsx`, иначе на сайте сырой ключ.
- Стили страницы → свой CSS-модуль, не глобальный `styles/graphic.css`.
- Картинки только через `next/image`. `poster`, `background-image` и `<img>` отдают камерные оригиналы по 13–21 МБ.

## Деплой

`git push origin main` → GitHub Actions (lint, type-check, test, build) → webhook на VPS 94.130.96.166 → `pm2 restart kishatattoo` → Cloudflare purge автоматически.
Push ≠ деплой: webhook отвечает 200 до `git fetch`. Проверка: `gh run watch` → curl живого URL → при сомнении `ssh … 'cd /var/www/kishatattoo && git log --oneline -1'`.
Перед пушем локально: `npm run type-check && npm test`.

## Как работаем

- Сессию начинаем с плана дня. Хук SessionStart показывает первый незакрытый день из `PLAN-IMPROVEMENTS-*.md`. После задачи отмечаем её там (`[x]` + результат).
- Тексты для сайта: du, короткие простые предложения, без двоеточий и тире, лид ~20 слов. Войстон блога в памяти `project_voicetone_blog`.
- Вопросы Стасу задаём текстом, по одному-два, не формами.
- Объяснения даём текстом в чате, без HTML-страниц.
- Платный запрос или запись во внешний сервис (Pinterest, GSC submit, Bing) — только в рамках задачи дня или по просьбе.
